## 1. 目的と前提

> [!IMPORTANT]
> <strong>結論: AWS の EC2 は使わない。</strong>理由は 3 点。既存アカウントの無料枠は 2017-02 に終了済み。EC2 に常時無料の枠は無い。最小クラス（`nano`・0.5 GB）は実用にならず、実用的な `t3.micro` は月 2,100 円ほど（概算・未確認）かかる。以降の章は、検討した内容の記録として残す。

- 目的（当初）: EC2 インスタンスを 1 台作成し、接続できることを確かめる。今のアカウントは無料枠が終了済みのため、少額の課金を前提にしていた
- 方針: 別のアカウントは作らない。既存のアカウントで進める
- 前提: AWS アカウントを持っている（無い場合は作成から）。ルートユーザでは日常作業をしない
- 作業場所: このプロジェクトに手順・スクリプトを残し、同じ構成を作り直せるようにする

## 2. 無料枠の調査結果

### このアカウントの状況（実測）

- 作成日は 2016-02-20（JST）。Gmail に残る AWS の歓迎メールの受信日で判定した
- 旧方式（作成から 12 か月）のため、無料枠は 2017-02 に終了済み（失効予告のメールも 2017-02 に届いている）
- コンソールの確認: 無料利用枠のページに使用中の項目は CloudWatch（常時無料）だけで、EC2 は無い。クレジットは残高 0 ドル
- 結論: **このアカウントの EC2 は無料ではない**。起動時間・EBS・パブリック IPv4 が通常料金で課金される

### 常時無料は無い

- EC2 に常時無料の枠は無い。常時無料はサーバを常駐させる種類ではない（Lambda・DynamoDB・CloudWatch・SNS・SQS の少量分など）
- EC2 の無料は期間限定のみ（旧方式は 12 か月、新方式はクレジットで最長 6 か月）

### 別アカウントを作る場合（採らない）

- 2025-07-15 以降に作った新しいアカウントには、新方式の無料プラン（クレジット最大 200 USD・最長 6 か月）が付く。しばらく無料で使える
- 別アカウントを作る方針は採らない。この選択肢は記録として残す

### 他社の常時無料枠（候補として残す）

- Google Cloud: `e2-micro` が 1 台、米国の一部リージョンで常時無料（東京は対象外）
- Oracle Cloud: Arm の VM（最大 4 コア・24 GB）などが常時無料。新規登録の審査が厳しい
- どちらも現行条件は未確認。採るときは公式ページで確かめる

### 最小クラスの月額（概算・未確認）

- 東京・24 時間稼働・EBS gp3 8 GB・1 ドル 150 円で計算。パブリック IPv4（約 3.65 ドル）を含む
- `t4g.nano` 約 8.4 ドル（約 1,300 円） / `t3.nano` 約 9.4 ドル（約 1,400 円） / `t3.micro` 約 14.3 ドル（約 2,100 円）

### 公式ページでの確認が要る点

以下は 2025-07-15 の無料枠改定時点の知識に基づく。**現在（2026-10）の公式ページで着手前に確かめる**。東京の `t3.micro` は稼働 1 時間あたり約 0.0136 USD（約 10 USD/月）と記憶しているが、未確認。

### 無料枠の一般条件（参考）

| アカウント作成日 | 無料枠の形 | 対象インスタンス |
|---|---|---|
| 2025-07-15 より前 | 作成から 12 か月、毎月 750 時間 | `t2.micro` / `t3.micro`（リージョンによる） |
| 2025-07-15 以降 | 無料プラン: クレジット（最大 200 USD）・最長 6 か月 | `t3.micro` `t3.small` `t4g.micro` `t4g.small` `c7i-flex.large` `m7i-flex.large` 等 |

- EBS: 30 GB（gp2/gp3）まで
- **パブリック IPv4 アドレスは 2024-02 から有料**（旧無料枠では 750 時間分が無料枠に含まれる）。新プランではクレジットから引かれる
- 確認先: AWS 無料利用枠のページ、コンソールの「Billing → 無料利用枠」

## 3. 構成案と決めること

決定: 1-A・2-A・3-A・4-A（各項目の A）。

### 1. 作成手段

- **1-A（推奨）AWS CLI のスクリプトで作る**: 手順が残り、作り直し・削除も同じスクリプトで行える
- 1-B マネジメントコンソールで手作業: 初回の理解には向くが、記録が手順書だけになる

### 2. OS

- **2-A（推奨）Amazon Linux 2023**: SSM Agent が最初から入っており、2-A の接続方式とそのまま組める
- 2-B Ubuntu 24.04 LTS: 情報が多い。SSM Agent は snap で入っている

### 3. 接続方式

- **3-A（推奨）SSM Session Manager**: 22 番を開けずに済み、鍵の管理も要らない。IAM ロールの付与が必要
- 3-B SSH（キーペア）: 22 番を自分の IP だけに開ける。鍵（`.pem`）は Git に入れない（.gitignore 済み）

### 4. リージョン・アーキテクチャ

- **4-A（推奨）東京 `ap-northeast-1`・`t3.micro`（x86_64）**: 新旧どちらの無料枠でも対象
- 4-B `t4g.micro`（Arm）: 新プランでのみ対象。x86 専用のソフトは動かない

## 5. 課金を防ぐ対策と後片付け

- 今のアカウントは無料枠が終了済み。起動した時間・EBS・パブリック IPv4 がすべて課金される。使わない間は終了（terminate）する
- インスタンスは 1 台だけ。常時動かすと月 730 時間ぶんが課金される
- 停止中も EBS・スナップショット・Elastic IP（未割り当て）は課金対象
- NAT ゲートウェイ・ロードバランサ・無料枠外のインスタンスタイプを使わない
- 削除はインスタンス終了 → EBS 残存確認 → セキュリティグループ・ロール削除の順
